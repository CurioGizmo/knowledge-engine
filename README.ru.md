## 🎯 Какую проблему решает платформа?

Большинство AI-ассистентов и автономных агентов (в Cursor, Claude Desktop, Windsurf, Roo Code, Antigravity) работают отлично на коротких дистанциях, но сталкиваются с фундаментальными барьерами на реальных проектах:

1. **Амнезия между сессиями:** Агент тратит часы на исследование неочевидного бага или выбор архитектуры, но уже в следующем диалоге забывает всё и снова наступает на те же грабли.
2. **Хаос в сложных задачах:** При разработке больших фич агент пытается сделать всё разом, теряет промежуточный контекст, пропускает важные шаги и застревает на полпути.
3. **Отсутствие регламента:** Агент действует «на свое усмотрение», не соблюдая принятые в команде процессы проверки, ревью и тестирования.

**MCP Knowledge Engine объединяет три инструмента, превращающие агента из «забывчивого собеседника» в системного инженера:**

---

## 🧠 1. Knowledge Engine — Долгосрочная память и база решений

Сервер отвечает за сохранение инженерного опыта и контекста проекта, который не должен теряться между чатами:

* **Уроки и архитектурные решения (ADR):** Агент фиксирует, *почему* в проекте было выбрано конкретное решение, какие библиотеки запрещены к использованию и какие грабли уже были пройдены.
* **Гипотезы и антипаттерны:** При расследовании сложных багов агент фиксирует рабочие гипотезы. Если идея оказалась тупиковой или опасной, она помечается как **антипаттерн** (`⛔`). Перед началом любой новой задачи агент проверяет базу знаний и никогда не предлагает опровергнутые решения повторно.
* **Контроль надежности:** Знания, подтвержденные человеком, помечаются защищенными от случайного автоматического изменения агентом.

---

## 🛠️ 2. Audit Engine — Пошаговые планы реализации и трекинг техдолга

Сервер структурирует процесс разработки и гарантирует, что сложные задачи выполняются дисциплинированно:

* **Пошаговые планы реализации (Implementation Plans):** Вместо спонтанного написания кода агент сначала составляет структурированный план. План разбивается на последовательные шаги с критериями готовности.
* **Последовательное выполнение и контроль шагов:** Агент выполняет задачу строго шаг за шагом. Каждый пройденный этап помечается выполненным с приложением доказательств (лог прогона тестов, ссылка на измененные файлы), и только после этого начинается следующий шаг. Прогресс виден человеку и переживает перезапуски сессий.
* **Граф зависимостей техдолга (DAG):** Задачи и техдолг фиксируются прямо в репозитории с указанием зависимостей (`blocked_by`). Агент автоматически получает в работу только те задачи, все блокеры которых уже закрыты.
* **История ревью:** Замечания по коду и результаты ревью привязываются к конкретным задачам и планам, создавая прозрачную историю разработки.

---

## ⚡ 3. Skills Engine — Модульные скиллы и собственные сценарии (Flows)

Сервер задает стандарты разработки и позволяет настраивать сквозные процессы под вашу команду:

* **Единые скиллы на несколько проектов (Общий каталог):** Скиллы и регламенты не нужно дублировать в каждый проект вручную. Skills Engine умеет загружать скиллы и сценарии из **внешнего общего Git-репозитория** (переменная `MCP_SKILLS_PATH` или аргумент `--skills-dir`). Вы обновляете скилл или сценарий в одном месте — и изменения сразу доступны агенту во всех ваших проектах.
* **Создание собственных сценариев разработки (Custom Flows):** Вы можете описать в виде простого Markdown-файла любой пошаговый процесс команды (например: *Анализ ТЗ → План реализации → Ревью плана → Написание кода → Тестирование → Документация*). Агент подключается к стейт-машине и идет строго по заданному маршруту.
* **Контроль этапов и обязательные проверки:** На каждом шаге можно зафиксировать правила перехода — например, агент не сможет начать писать код, пока человек не утвердил план реализации, и не сможет закрыть задачу, пока не пройдут тесты. Это исключает галлюцинации и пропуск обязательных стадий.
* **Адаптация под стек проекта:** Скиллы не перегружают контекст общими рассуждениями — сервер автоматически распознает стек проекта (FastAPI, React, SQLite, Postgres и др.) и подмешивает в инструкции агента только релевантные фрагменты.
* **Локальные переопределения в проекте:** Если конкретному проекту требуются уникальные сценарии или дополнения, их можно положить локально в `.agents/skills` — они мягко дополнят общий каталог.

## ⚡ Как это устроено под капотом

* **Память и планы — в репозитории проекта (`.agents/`):** База знаний (Knowledge Engine) и пошаговые планы реализации (Audit Engine) хранятся непосредственно в Git-репозитории проекта в каталоге `.agents/` как обычные Markdown-файлы с YAML-заголовками. Их можно коммитить, читать глазами и обсуждать в стандартных Pull Request.
* **Общие скиллы — во внешнем репозитории:** Каталог скиллов и сценариев (Skills Engine) берется из внешнего общего репозитория (по умолчанию кэшируется в `~/.cache/mcp-skills/repo`), что позволяет переиспользовать единые инженерные стандарты между десятками проектов без копирования файлов.
* **Мгновенный локальный поиск:** Сервер автоматически поддерживает локальный полнотекстовый FTS5-индекс в SQLite (`.cache/`). Поиск по ключевым словам и семантике занимает меньше 1 миллисекунды.
* **Без серверов и облаков:** Никаких баз данных, Docker-контейнеров, подписок или внешних API-ключей. Нужен только Python 3.11+.

## 🚀 Быстрый старт: подключение к любому AI-клиенту

Платформа работает по открытому стандарту **Model Context Protocol (stdio)** и одинаково легко подключается к **Cursor, Claude Desktop, Windsurf, VS Code (Roo Code / Cline), Antigravity, OpenCode**.

### 1. Способы подключения к клиентам

Вам **не нужно жестко прописывать пути к проектам** — сервер автоматически определяет открытый в редакторе репозиторий (по `.git`, `pyproject.toml` или рабочей директории клиента) и привязывается к нему на лету.

#### Вариант А: Без установки через `uvx` (Рекомендуется)
Клиент сам запускает нужные версии серверов в изолированном окружении:

```json
{
  "mcpServers": {
    "knowledge-engine": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/CurioGizmo/knowledge-engine.git", "mcp-knowledge-engine"]
    },
    "audit-engine": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/CurioGizmo/knowledge-engine.git", "mcp-audit-engine"]
    },
    "skills-engine": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/CurioGizmo/knowledge-engine.git", "mcp-skills-engine"]
    }
  }
}
```

#### Вариант Б: При глобальной установке через `uv tool`
Если вы установили платформу глобально:
```bash
uv tool install git+https://github.com/CurioGizmo/knowledge-engine.git
```
В настройках клиента достаточно указать прямые команды — без аргументов и путей:
```json
{
  "mcpServers": {
    "knowledge-engine": {
      "command": "mcp-knowledge-engine"
    },
    "audit-engine": {
      "command": "mcp-audit-engine"
    },
    "skills-engine": {
      "command": "mcp-skills-engine"
    }
  }
}
```

*(Для локальной разработки самого движка из исходников можно передавать `args: ["run", "--directory", "/путь/к/mcp-knowledge-engine", "..."]`).*

> 💡 **Для пользователей Antigravity / Gemini CLI:**  
> Все три сервера и сопутствующие плагины можно подключить одной командой:  
> `uv run mcp-engine-install --skill`

## 📦 Релизы и пакеты
 
Готовые пакеты wheel (`.whl`) и исходные архивы (`.tar.gz`) автоматически собираются через GitHub Actions и прикрепляются к каждому GitHub Release.
 
Для локальной сборки пакетов из исходников:
```bash
uv build
```
Собранные файлы появятся в папке `dist/` и могут быть установлены в любое окружение:
```bash
uv tool install dist/mcp_knowledge_engine-0.5.0-py3-none-any.whl
```

## ❓ Часто задаваемые вопросы (FAQ)

**Где физически сохраняются файлы?**  
Все данные сохраняются в папку `.agents/` в корне вашего проекта:
* `.agents/knowledge/` — база знаний, решения (ADR) и антипаттерны.
* `.agents/plans/` — пошаговые планы реализации.
* `.agents/audit/` — задачи и технический долг.
* `.agents/flows/` — ваши пользовательские сценарии разработки.

**Как агент понимает, в какой проект сохранять данные?**  
Сервер автоматически определяет корень проекта, поднимаясь вверх от текущей рабочей директории до маркеров `.git`, `pyproject.toml` или `package.json`. Также путь можно передать явно флагом `--project-root /путь/к/проекту` или через переменную `MCP_PROJECT_ROOT`.

**Что делать, если поисковый кэш рассинхронизировался?**  
Кэш полностью эфемерный. Удалите файл `.agents/.cache/*_fts.db` — при следующем обращении сервер автоматически переиндексирует все карточки менее чем за 50 мс.
